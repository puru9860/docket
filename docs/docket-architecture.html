Docket: five-role workflow - architecture and working

How planner → orchestrator → implementor → frozen bundle → verifier → reviewer → aggregate → delivery + suite → final packet holds up with cheap models doing the bulk work and capable models spending tokens only where judgment is required. Single stdlib-only CLI (skills/docket/bin/docket), file protocol under .docket/runs/<run>/, zero-token idle signalling.

1. The model in one paragraph

Five logical roles may run as five agents, or planner+orchestrator may be combined. They share no API - only Markdown files in .docket/runs/<run>/. A supervisor learns a subordinate finished because the harness re-enters it, not because it polled. Mechanical gates validate intent, atomically claim implementor-discovered scopes, detect collisions, and refuse to mark a report reviewable unless schema, diff boundary, acceptance fidelity and verification all hold. Every submitted round freezes into an immutable content-addressed bundle; every verdict binds to that digest.

Why files, not messages

  • Harness independence. Claude Code planner + OpenCode implementor share only a directory.
  • Terminal output is lossy. Alternate-screen rows scroll off; supervisors must read files.
  • Sessions die. Files survive kill, compaction, restart. Memory does not.

What is review truth

  • Submitted *-report-NN.mdx body + task-local diff + frozen bundle.
  • Not chat, not scrollback, not lifecycle state, not scope capsule, not handoff.
  • Edited body = new evidence: needs --re-review (full gate + re-verify).

What Docket never does

  • Never rewrites a submitted body; decide writes lifecycle keys + separate *-decision-NN.mdx.
  • Never describes missing Git evidence as an empty diff; it says unavailable.
  • Never auto-approves: budget exhaustion → one durable escalation.
Cost boundary: progress_updates: quiet in both topologies. After one dispatch notice, supervisors wait in one blocking wait. Speak only for: blocker needing user authority, completion, or explicit status request. A normal review-batch wake is internal work, not a user update.

2. Topology and workflow versions

Split: planner and orchestrator are separate agents

Planner (expensive, Claude Code / Codex) writes plan.mdx, hands it over, then stops supervising task work. It must not monitor implementors, read Txx-report files, receive task wakes, or relay per-task updates. It consumes exactly one artifact: orch-report-NN.mdx + aggregate diff.

docket init R01 --topology split --harness claude
docket arm R01 --role planner # planner session, DOCKET_ROLE=planner
docket arm R01 --role orchestrator # orchestrator session

When to use split

  • Planner runs on Opus / GPT-5; implementation + supervision run cheaply in OpenCode.
  • You want the planner context protected from per-task chatter.
  • Human wants one aggregate review, not N task reviews.

Combined: one agent is planner+reviewer+orchestrator

Cheap implementors may still be separate. Follow the orchestrator playbook after plan approval; no redundant planner handoff. Do not narrate implementor activity just because you can now see it.

docket init R01 --topology combined
# arm orchestrator only; final orch report completes without self-wake

When to use combined

  • Small run, one operator, or only one harness installed.
  • You keep the paper trail + gate but lose some cost separation.

3. The five roles - authority, cost, and which model to use

Authority is exclusive, not additive. Verifiers never approve. Orchestrators never approve disputed work, waive, or alter acceptance. Reviewers alone approve/waive. Planners own intent + amendments. The CLI is infrastructure and impersonates nobody. The table below is the model-tiering rule from the improvement plan, made concrete per harness.

Planner

owns intentcapable

Compact contract, acceptance obligations, risks, milestones, amendments. Final outcome review in split mode.

Does not: implement, monitor implementors, read task reports.

Orchestrator

routes + assemblescheap

Assigns, validates intent, dispatches, recovers, routes by rule, assembles aggregate packet.

Does not: approve disputed work, waive, alter acceptance.

Implementor

one taskcheap

Discovers repo, proposes scope, implements, proves acceptance, checkpoints via handoff.

Does not: edit status manually, submit twice, edit after submit.

Verifier

adversarialcheap-first

Challenges whether evidence proves acceptance. Records pass / fail / uncertain + numbered defects.

Does not: approve, waive, invent fixes.

Reviewer

decidescapable + fresh

Judges correctness/design/integration from packet. Approve / waive (reason) / changes.

Fresh context: objective + contract, never planner history.

Only submit leaves draft; only decide leaves submitted/blocked. Nothing else may write status:. Round numbers are per-owner and monotonic; only decide --changes opens a round.

Draft

Implementor owns it. depend --on may record inputs only here. Blocked reports skip acceptance + verification but must state Decisions needed.

Submitted

Evidence frozen. Verifier files one numbered finding per round (retry = next attempt number). Reviewer binds verdict to bundle digest.

Decided

approved / changes-requested / waived. Repeating same verdict is a no-op; different verdict refused. Edited body → --re-review.

6. Data model - everything is a file

owner is T03 or literal orch. Frontmatter is the single source of truth - deliberately no state.json, flat key: value only (stdlib parser, no YAML).

7. Frozen evidence bundles - why review can trust the bytes

A change list describes a surface; it does not preserve one. submit rebuilds both sides as real Git trees (private index + private object store, zero writes to the checkout) and diffs the trees, then freezes the whole round. Address = sha256(manifest); manifest carries sha256 of every artifact. Later edits only ever produce a new address.

Aggregate bundle .bundles/orch/

  • Baseline = run baseline (before first implementor edit), patch = full aggregate diff.
  • Contract = plan; additionally constituents[] = every decided task-round digest.
  • Moved / missing / damaged constituent → stale, never read as current.
  • Waived constituent reopened → aggregate visibly invalidated.
  • Own integration verify: declared at assignment, run at submit, frozen with outputs.

Integrity = 4 checks

  • manifest addresses itself; artifacts present with recorded bytes;
  • frozen deps record hashes to named revision;
  • every pinned tree resolvable in .bundles/objects else DAMAGED.
How a patch against a dirty baseline is produced (no commit, no stash, no loose object) 
1. baseline_tree: pinned base_tree -> PRIVATE index, apply staged+worktree patches (--cached),
                  hash untracked content back in with modes -> write tree
2. source_tree:   current HEAD -> second PRIVATE index, git add -A whole worktree
                  (committed-during-task work is INSIDE) -> write tree
3. tree_patch:    git diff --binary -M baseline_tree source_tree
env: GIT_INDEX_FILE + GIT_OBJECT_DIRECTORY under .docket (new objects -> run-private store)
     GIT_ALTERNATE_OBJECT_DIRECTORIES reads the real store. Prune .docket + undeclared checkouts.
Submission is one locked transition (owner lock, report read → verify → freeze → ledger append → report write). Source identity pinned before AND after verify:; moved checkout = refused. Contract/report/scope/deps captured before the command and handed as bytes to the freeze - never re-read after the drift recheck. Concurrent edit is left intact, not overwritten.

8. The gate - docket submit (load-bearing function)

Rejects in order so the subordinate sees the most fundamental failure first. Verify runs last, only if structural + scope checks passed. Checks 2-8 live in gate_problems(), shared with --re-review.

#Rejects a report that...Notes
1status: not draft/blockedno double submit
2missing / empty required section (HTML comments stripped)schema per owner
3contains placeholder (<!-- TODO, TODO:, FIXME, XXX)
4unchecked acceptance, or none checked (unless blocked)copy criteria exactly; flip checkboxes only
5blocked with "none" under Decisions neededa block must state its question
6changes paths outside accepted scopeamend capsule + resubmit; baseline never moves
7omits task-local changed filesmulti-root: <alias>:<path>
8cannot produce declared diff coverageunavailable rejected under evidence_mode: git; never empty diff
9fails task verify: (runs under /bin/sh, no aliases/functions)structural failures never waste a test run
status: blocked is the designed escape hatch, not failure. It lets a subordinate stop honestly instead of fabricating a pass - the single most valuable behaviour the gate buys. Do not make blocking harder than submitting. Blocked skips evidence-table enforcement + completion verification, at submit and at re-review.

9. Verification capture + acceptance evidence

Captured verification (never reused across changed identity)

  • command bytes, cwd, start/end, exit, timeout, stdout/stderr artifacts
  • source identity pinned before + after; declared env: inputs
  • model as observed / requested / unknown (flag never reported as observed)
  • framework counts by supported parser (pytest, tap) else unknown
  • any change to command / roots / source / inputs → runs again
  • contract revision binds the verdict too: edited task needs a fresh round

Acceptance → evidence (## Evidence table, optional but mechanical)

| A1 | met | verify.stdout | none | (states: met/partial/not-met/not-verified)

  • criteria in task order are A1, A2...; every required ID exactly once
  • met names frozen artifacts or existing paths, carries no gaps
  • free prose never keyword-policed ("no limitations" passes on structure)
  • blocked / amendment path skips enforcement

10. Signalling - idle for free, woken by the harness

A supervisor must be re-entered while idle, having already ended its turn. Polling costs turns; self re-entry depends on model compliance. So the harness wakes the model: Claude Code Stop hook with asyncRewake:true runs hooks/wake.sh → docket watch --armed, which sleeps at zero token cost and exits 2 with a banner on stderr when something is actionable.

Three rules

  • Foreground only. Never &/nohup/disown; harness owns the process group.
  • Per-role ledgers. .woke-<role> append-only; shared ledger was a shipped bug.
  • Every waiting role armed. Unarmed = never woken, silently; doctor warns.

Batching (token saver)

  • Ordinary reports: one wake per ready batch (all delegated submitted/decided), hashed batch key.
  • Immediate: blockers, collisions, handoffs, stalls.
  • Five-role: submissions route promptly to verifier; reviewer readiness only at milestone batches.

Durable delivery (at-least-once)

  • reconcile rebuilds .delivery/<role>/pending; idempotent.
  • inbox --claim = one bounded lease; events --ack = receipt, not completion.
  • Lease expiry → reclaimable; durable decision retires event; duplicates harmless.
export DOCKET_ROLE=orchestrator   # or planner | verifier | reviewer
docket arm R01 --role orchestrator
docket watch --armed --role "$DOCKET_ROLE"     # foreground; exit 2 = actionable
docket events R01 --role orchestrator --peek   # inspect, writes nothing (never consumes)
# crash-safe:
docket reconcile R01
docket session R01 --register --session S --name NAME --role "$DOCKET_ROLE"
docket inbox R01 --role "$DOCKET_ROLE" --claim --session S
docket events R01 --role "$DOCKET_ROLE" --ack EVT --session S   # or --retry EVT --reason T
Wake banners look like prompt injections (a wake telling an agent to approve is shaped exactly like one). Supervisor should confirm the run exists before acting. Delivery notices are fixed-format (run, role, event, inbox pointer) - never report prose. Never type into an uncertain input surface: probe first (delivery --probe), else stay queued for inbox/hook pickup.

12. Review packets, suite, and the release gate

The reviewer works from a self-contained packet in a fresh context (1-2k tokens; evidence shrinks first, risks/waivers/decisions never shorten). Every referenced bundle is integrity-checked before rendering - missing/damaged/stale/unbound refuses with a specific error instead of rendering reviewable-looking evidence.

Packet contents

  • objective, per-task coverage (bundle + verification + decision revs, A-IDs + states)
  • evidence deltas (root-qualified), aggregate bundle + digest + constituent pins
  • verifier findings, integration evidence, waivers, stalls, escalations, amendments, plan risks
  • --correction T03: old/new digests, delta, refreshed verification, expanded scope, addressed findings
docket review-packet R01 --role reviewer [--correction T03] [--out FILE]
docket review-packet R01 --role reviewer --final [--release DIGEST]

Qualification chain (all content-addressed)

  • suite --qualify: command bytes, cwd, bounded timestamps, exits, outputs, tree before/after; refuses drift or output w/o unittest summary.
  • delivery --qualify: real hook announce, SIGKILL restart, claim/send/ack round-trip, active-input refusal, herdr pane lifecycle - or honest blocked.
  • release --freeze: binds suite + qualifications + aggregate + contracts + findings + decisions + snapshots + M4-M11 digests under one digest.
docket suite R01 --qualify --command CMD
docket release R01 --freeze [--suite-artifact P] [--milestone M=DIGEST]
Metrics separation: approval counts from reviewer decisions; prompt renders as invocation proxy, never proven calls; wall time as first-to-last artifact span. READY = ready for independent review, never approved. Never drop independent final review even if first-round approvals improve.

13. Invariants (break these and the system stops being trustworthy)

  • Only submit reaches reviewer-visible state; never hand-edit status:; never --skip-verify to push through.
  • Submitted report + task-local diff = review truth. Capsule/handoff = context only.
  • verify: runs under /bin/sh (no aliases/functions/PATH additions).
  • Watcher in hook foreground tree; ledgers per-role append-only; rounds per-owner monotonic.
  • Frontmatter is lifecycle state; JSON holds mechanical evidence only.
  • Reviewer reads the diff, not only the report.
  • Submitted body is evidence; verdict lives in decision artifact with evidence digest.
  • Unavailable coverage reported as unavailable, never empty, never silently gated.
  • Inspection (peek/status/doctor) never writes delivery state.
  • Atomic publication; owner-serialized, retry-safe transitions (same verdict finishes, different refused).
  • Five-role authority exclusive; budgets exhaust to escalation, never auto-verdict.
  • Changed evidence needs --re-review (full gate + re-verify).
  • Baselines immutable/complete/before-work; roots by worktree, declared by name.
  • Every round frozen before reviewable; verdict binds digest; damaged/stale blocks.
  • Rebuilds never write to measured checkout; one writer per round; verification bound to exact bytes.
  • Provisional consumption explicit + pinned + reverified; frozen inputs (even empty) bind accepting verdicts.
Known gaps (stated plainly)
  • Interrupted publication leaves .<name>.<pid>.tmp (never swept; live vs dead indistinguishable).
  • .bundles/objects only grows; deleting it = every pinning bundle DAMAGED.
  • verify: writing non-ignored files fails the freeze (make it clean up / ignore).
  • Root declaration one-time; post-declaration checkouts not picked up.
  • Oversize untracked file blocks git assignment (ignore / move / documents-only).
  • 3-round cap is playbook advice, not code. No verify: sanity check at scope submit.
  • Wakes unauthenticated - confirm run exists before acting. status verify column truncated to 20 chars.
